## Problem

Accepted `main` has no Source registry, Work registry, Source↔Work bindings, or source-lineage state. Multiple research proposals are therefore blocked from governed promotion and must remain staging/proposal work.

The missing registry is a Librarian-owned dependency. Series, film, literature, migration, and Consolidator workers must not independently mint competing canonical Work or Source identities to bypass it.

## Routed bounded tranche

The Librarian should produce one first bounded registry/source-binding proposal with these properties:

1. Define repository records for concrete Source instances and governed Work units using the accepted/proposed schema contract once architecture admission is adequate.
2. Preserve Source and Work as distinct identities. A transcript page, audiovisual release, ebook file, conversion, container, API snapshot, or dataset record is not automatically the Work itself.
3. Record source variant/version, retrieval identity, stable hash where byte custody permits, lineage/provenance family, and independence grouping.
4. Treat external IDs and metadata as crosswalk/discovery evidence, not canonical Trek IDs or automatic truth.
5. Do not derive canonical Work identity from worker staging titles, page headings, filenames, or remembered franchise lists alone.
6. Where byte custody is unavailable, preserve DISCOVERED/UNRESOLVED state rather than fabricating SOURCE_BOUND.
7. For transcript providers with observed page-heading/body mismatches, bind to the actual retrieved source representation and preserve the metadata anomaly explicitly.
8. For literary containers/conversions, resolve container-versus-contained-work and derivative-family questions before deep-reading admission.

## Priority guidance

Clearing works already represented in staging proposals can unlock multiple lanes, but registry priority remains preference-blind and provenance-driven. Do not distort source inventory merely to reward whichever worker produced the most staging packets.

A practical first audiovisual tranche may include a small set spanning currently blocked staging lanes only if the Librarian can verify their source identity reproducibly. A practical literary tranche begins with byte custody and source-family reconciliation rather than title matching.

## Admission output expected

The first proposal should make it possible to answer, deterministically and without chat memory:
- what Work is being referenced;
- which concrete Source instance(s) support it;
- whether those source bytes/representations were actually available;
- how source variants relate;
- whether apparently independent records share upstream lineage;
- which coverage tier is justified and which is not.

## Non-authority

This route does not create Source IDs, Work IDs, crosswalks, source hashes, accepted coverage, identity reconciliation, or any merge/protected effect. Those remain owned by the appropriate governed role and acceptance process.
