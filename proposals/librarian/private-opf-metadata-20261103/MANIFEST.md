## What was actually processed

- All **347** OPF metadata entries were enumerated deterministically, their **original unmodified entry bytes SHA-256 hashed**, and selected XML metadata elements (`Title`, `Creator`, `Publisher`, `Date`, `Language`, `Identifier`) inspected.
- **332** entries parsed strictly as XML. **15** entries contained `dc:` metadata prefixes but lacked the namespace declaration required by a strict XML parser; their metadata was recovered by adding the missing namespace **in memory for parsing only**. Original entry bytes and their hashes were left unchanged, and each carries `OPF_XML_NAMESPACE_RECOVERED` status.
- 347 entries have OPF-declared title strings; 264 have creator strings; **75 entries contain at least one syntactically/checksum-valid ISBN candidate**. A valid ISBN check digit is **not proof of the book edition, publisher or rightful source association**.
- No private OverDrive/device GUID, raw archive-member path, ebook text, image, cover, PDF, synopsis or dialogue is exported. Public files contain title/creator/publisher/date/language **metadata observations**, checksum-valid ISBN candidates, source-local IDs and source byte hashes only.

`observations.json` is the exact bounded host-observed, metadata-only snapshot; `search-index.json` is a deterministic derivative that provides lowercased, Unicode-normalized **title, creator and ISBN search keys** keyed by source-local OPF entry ID. These are **search leads** for a later separately authorized Explorer ingestion, *not* canonical Work identity, publisher-confirmed editions or approved content. Two OPF entries might describe one Work, and one OPF entry might describe an anthology, omnibus or ebook bundle. This tranche does not deduplicate them semantically.

> **Hostile challenge:** An OPF may be stale, mislabeled, incomplete, or generated by an unofficial converter. For example, a truncated creator field such as `John` is only the actual OPF claim; it is not verified authorship. A checksum-valid ISBN is only a candidate identifier. No downstream projection may treat these records as `SOURCE_BOUND`, `FULL_TEXT_AVAILABLE`, `CLOSE_READ`, edition-bound or globally reconciled without new evidence and an accepted reviewer decision.

## Protected boundaries and reproduction

- `SOURCE → WORK` binding: **unresolved**; accepted Source/Work admissions: **0**; governed coverage effect: **0**.
- External edition validation: **0**; editorial synopsis approvals: **0**; copyrighted images/text published: **0**.
- The raw path map for resolving opaque IDs stays on the owner host; it is **not committed**. The original private archive is required to reproduce source hashes from bytes.
- The committed compiler checks a **pinned operator-observed JSON snapshot**, not the owner's private ZIP. Its tests therefore validate deterministic projections, privacy constraints and declared fingerprints; they do **not independently prove** the ZIP's container digest, reject malicious ZIP members at extraction time, or revalidate XML from the private host. Separate host-only source checks and independent review remain necessary.
- Independent host-only audit rechecked the container digest and source OPF bytes, with an exact multiset match over all **347** OPF entry fingerprints. The same audit found no duplicate ZIP names or traversal members and confirmed **332 strict XML parses plus 15 unbound-namespace exceptions**. It also found external document-type declarations in the OPFs (no internal entity declarations observed). Future raw-XML extractors must disable external entity resolution and impose ZIP/member read limits; the committed derivative compiler deliberately does not attempt XML/ZIP extraction.
- Public derivative validation: `python tools/build_private_opf_metadata_index.py --check`; adversarial checks: `python -m unittest tests.test_private_opf_metadata_index -v`.
- The compiler fails closed on source-file digest drift, duplicate JSON keys, missing/duplicate rows, changed private-container metadata, bad ISBN check digits, leaked private paths/identifiers, false parse recovery or attempted admission.
- The source-local entry-fingerprint multiset guard `532db2000ea03e2aabd713f31557552ce57c6eefe0b2eb18f8e1643c3127c0b4` is SHA-256 over the **UTF-8 bytes of all 347 lowercase hexadecimal entry SHA-256 strings sorted lexicographically and concatenated without delimiters**. This is a deterministic snapshot guard, separate from the independent host auditor's fingerprint-list digest convention.
