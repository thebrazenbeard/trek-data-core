## Disposition

**CONTESTED / NOT ACCEPTANCE-READY.**

The event model gets several important #40 principles right: coverage states are explicit and append-only; no later state is inferred merely from an earlier event; SOURCE_BOUND is binding-dependent; source-specific early states preserve Source context; producer roles are constrained for research/integration/audit states; correction/supersession history remains inspectable; missing denominator can be represented as unresolved; and producer validation is not automatically AUDITED.

The current implementation still trusts self-declared coverage provenance and arbitrary discovered Work records too much. As written, a syntactically valid event chain can create accepted coverage without proving the underlying accepted batch/audit/integration result, and proposal/migration Work/events can contaminate denominator/reporting if present in the scanned checkout.

## Confirmed strengths

1. Independent states exactly preserve the governed ladder: DISCOVERED, SOURCE_BOUND, FULL_TEXT_AVAILABLE, STRUCTURALLY_INDEXED, CLOSE_READ, SEMANTICALLY_ANALYZED, ENTITY_LINKED, CROSS_REFERENCED, AUDITED.
2. `active_events()` keeps append-only history while allowing accepted/rejected corrections to deactivate a predecessor.
3. SOURCE_BOUND requires an ACCEPTED EVIDENCE_BEARING Source↔Work binding matching Work/Source context.
4. FULL_TEXT_AVAILABLE requires Source-specific representation type + completeness scope.
5. STRUCTURALLY_INDEXED/CLOSE_READ/SEMANTICALLY_ANALYZED preserve the same Source through their explicit predecessor chain.
6. CLOSE_READ/SEMANTICALLY_ANALYZED require research-lane producer roles; ENTITY_LINKED/CROSS_REFERENCED require CONSOLIDATOR; AUDITED requires AUDITOR.
7. Proposed events do not enter active accepted coverage.
8. Missing Work records produce `DENOMINATOR_UNRESOLVED` rather than a fabricated percentage.
9. The synthetic tests correctly prove that mere Source/local-entity/producer activity does not auto-promote later coverage states.

## Blocking findings

### AUD-COV-001 — CRITICAL — producer/basis references are unverified strings, so accepted work can be self-declared

`coverage_event` requires nonempty `producer_ref` and `basis_refs`, but `validate_coverage()` never resolves either field to an accepted governed artifact.

Consequences:

- a TNG-tagged event can claim ACCEPTED CLOSE_READ with `producer_ref: "fixture:anything"` and arbitrary basis strings as long as an accepted predecessor event chain exists;
- SEMANTICALLY_ANALYZED can likewise be self-declared without proving neutral coding/evidence/assertion generation/validation;
- ENTITY_LINKED/CROSS_REFERENCED require a nonempty `integration_ref` but do not resolve it to accepted reconciliation/integration state;
- AUDITED requires `producer_role=AUDITOR` + nonempty `audit_ref`, but does not verify that `audit_ref` identifies an actual accepted audit result with matching Work/scope/disposition.

Director #40 explicitly says accepted CLOSE_READ must point to completed batch evidence and AUDITED must come from an audit result rather than producer activity. Role strings plus opaque references do not establish that provenance.

Required fix: define typed basis/provenance references per state and resolve them against accepted governed records, including exact Work/Source/scope compatibility. Fail closed when the referenced research batch, reconciliation/integration record or Auditor finding is absent/proposal-only/rejected/mismatched.

### AUD-COV-002 — CRITICAL — scan surface permits proposal/migration coverage leakage

`scan_typed_records()` scans `research`, `external`, `migrations`, `coverage`, and `registry`, collecting any `coverage_event` object it encounters.

There is no authoritative-ledger path/ownership check here. An `ACCEPTED` coverage event preserved under a worker staging/migration/external proposal path can therefore become active input to `coverage_report()` if the rest of its shape/prerequisites pass.

This violates the core rule that proposal/staging workload never advances accepted coverage.

Do not rely on Git branch social convention alone. Coverage tooling should consume only a governed authoritative coverage ledger/root, or tag/verify accepted-origin provenance explicitly. Worker/migration-local coverage notes must remain non-authoritative even if they contain the string `ACCEPTED`.

Required adversarial fixture: a syntactically valid ACCEPTED CLOSE_READ event under a worker/migration staging path must contribute **zero** accepted coverage and preferably fail authoritative-ledger validation.

### AUD-COV-003 — CRITICAL — denominator can be "RESOLVED" from arbitrary Work records with no accepted registry snapshot/scope

`coverage_report()` sets:

`denominator_status = RESOLVED if works else DENOMINATOR_UNRESOLVED`

and `work_denominator = len(works)`.

The default `works` index comes from every scanned `work` record across research/external/migrations/coverage/registry.

This does not satisfy #40 denominator discipline. A denominator must identify the accepted Librarian Work-registry snapshot/head and meaningful scope (lane/medium/collection/contained-work semantics). Migration-local or fixture/proposal Work records must not make a denominator resolved.

The current report also emits one global Work denominator with no lane, medium, continuity/collection scope or registry-head receipt. That creates the exact universal-percentage gravity #40 prohibits.

Required fix:
- consume only accepted Librarian-owned Work registry records;
- require/pin accepted registry head/snapshot identity;
- require an explicit reporting scope (at least lane/medium or other governed denominator scope);
- report `DENOMINATOR_UNRESOLVED` when that scoped accepted registry is unavailable, even if unrelated Work objects exist elsewhere in the checkout.

### AUD-COV-004 — HIGH — SOURCE_BOUND trusts binding fields without validating the binding contract/source lineage

`validate_coverage()` indexes any `source_work_binding` record and checks only status, mapping_role and matching source/work IDs.

It does not execute the #125/#65 binding schema/validator, verify binding scope/content-grounded basis/supersession/exclusivity, or ensure the binding is authoritative Librarian state rather than a malformed/ad hoc proposal object.

PR #138 is correctly stacked before accepted #125 integration, so fail-closed SOURCE_BOUND is expected today. Once the binding surface is integrated, coverage validation must consume **validated active accepted binding state**, not duplicate three fields from it and assume the rest.

### AUD-COV-005 — HIGH — prerequisite events prove only ledger ancestry, not substantive prerequisite completion

The immediate-predecessor checks are deterministic and useful, but they inherit whatever truth the predecessor event asserted.

Once a fabricated/unverified CLOSE_READ event enters the ledger, SEMANTICALLY_ANALYZED can legitimately point to it and pass. This is why AUD-COV-001 is load-bearing: prerequisite chains must terminate in real accepted source/batch/integration/audit provenance, not just mutually consistent event objects.

### AUD-COV-006 — MEDIUM/HIGH — schema/method/registry identity is carried but not governed/verified

Events require `schema_version` and `methodology_version`, and optionally `registry_head`, but the validator accepts arbitrary nonempty strings and never checks them against the governing accepted versions/snapshot.

For historical append-only events, old versions may be legitimate. The correct behavior is not "must equal current"; it is "must identify a real governed version/snapshot and preserve it." Add resolvable/versioned identity validation rather than accepting opaque text.

### AUD-COV-007 — MEDIUM — reporting loses Source/representation distinctions in covered-work counts

Early ledgers correctly key active event uniqueness by Source, but reporting collapses each state to unique Work IDs. A Work with two accepted Source-specific FULL_TEXT_AVAILABLE events is reported only as one covered Work, with no representation/source breakdown.

That is fine as a summary metric only if the report also preserves source/representation-level counts/details. #40 requires distinct source-binding/full-source ledgers and medium-specific context; do not let the convenience Work count become the only visible denominator/numerator surface.
