- `ADDED_FACT`;
- `REMOVED_FACT`;
- `VALUE_CHANGED`;
- `STATUS_PROMOTED`;
- `STATUS_DEMOTED`;

These are substantive improvements.

## Remaining findings

### AUD-ARCH-004A — local entity additions/removals and non-link entity changes are invisible

**Verdict:** CONFIRMED  
**Severity:** CRITICAL

`entities.jsonl` is examined only for IDs present in **both** projections and only for the `resolved_entity` field.

Therefore the semantic diff currently emits no entity change for:
- a newly added local entity;
- a removed local entity;
- changed Work association;
- changed label or any other local-entity field;
- other future entity metadata changes when the resolved global link is unchanged.

A canonical projection can therefore change its entity state while `semantic_diff()` reports no corresponding change record.

**Required correction:** every canonical-output change must be represented. If the governed taxonomy intentionally has no `ADDED_ENTITY`/`REMOVED_ENTITY`, use an explicit governed extension or at minimum a non-silent `VALUE_CHANGED` operation for entity creation/removal/value changes. Do not ignore them.

---

### AUD-ARCH-004B — `CONFLICT_RESOLVED` is overclaimed for conflict→UNRESOLVED transitions

**Verdict:** CONFIRMED  
**Severity:** HIGH

The implementation defines conflict states as `CONTESTED` or `STRUCTURAL_PARADOX`. Any transition from one of those states to a non-conflict state emits `CONFLICT_RESOLVED`.

That means:
- `CONTESTED -> UNRESOLVED`;
- `STRUCTURAL_PARADOX -> UNRESOLVED`

are labeled `CONFLICT_RESOLVED`.

Under the Project method, `UNRESOLVED` is a legitimate unresolved epistemic result, not proof that a contradiction/conflict has been resolved. A transition may mean the prior conflict classification is no longer justified while the underlying proposition remains unresolved.

**Required correction:** do not equate `not currently classified as conflict` with `conflict resolved`. At minimum reserve `CONFLICT_RESOLVED` for a governed transition whose semantics establish resolution, such as conflict→STABLE, or require an explicit conflict-resolution representation.

Add negative fixtures for contested/structural-paradox -> unresolved.

---

### AUD-ARCH-004C — relation projection changes are ignored entirely

**Verdict:** CONFIRMED FUTURE-BLOCKER  
**Severity:** HIGH

The canonical logical projection includes `relations.jsonl`, but `semantic_diff()` never loads or compares it.

PR #59 intentionally emits an empty relation file today because fact-vs-relation predicate semantics are not governed yet. That fail-closed behavior is sound. Once relations become non-empty, however, PR #64 would silently ignore relation additions/removals/value changes.

**Required resolution:** before `relations.jsonl` may be populated, govern relation diff semantics or fail closed when non-empty relation outputs are encountered. Silent omission is not acceptable.

---

### AUD-ARCH-004D — residual assertion-field changes can be invisible

**Verdict:** CONFIRMED  
**Severity:** HIGH

For assertions present in both projections, the classifier explicitly compares only:
- projection status;
- `subject`, `predicate`, `object`;
- `resolved_subject`;
- `scope` / `resolved_scope`.

Canonical assertion rows can contain additional meaningful fields such as:
- evidence list;
- assertion supersession/history fields;
- projection reason;
- decision provenance fields;
- future governed assertion fields.

Some evidence changes also alter `provenance.jsonl`, but the diff tool should not rely on an indirect side effect to ensure every changed canonical assertion row is classified.

After recognized semantic classes are extracted, compare the residual canonical row and emit a deterministic fallback `VALUE_CHANGED` (with changed fields) for otherwise unclassified differences.

---

### AUD-ARCH-004E — provenance group creation/removal is not compared

**Verdict:** CONFIRMED DEFENSIVE GAP  
**Severity:** MEDIUM

Provenance is compared only for assertion IDs present in both old and new provenance group keys.

If an existing assertion's provenance group appears or disappears entirely, no `PROVENANCE_CHANGED` record is emitted for that assertion. Valid current projections normally generate at least one provenance row for every accepted assertion, but a semantic diff should detect malformed/contract-transition output rather than silently ignore it.

Compare the union of provenance assertion IDs and classify group addition/removal explicitly.

---

### AUD-ARCH-004F — new conflicted assertions do not emit CONFLICT_INTRODUCED

**Verdict:** PROVISIONAL CONTRACT GAP  
**Severity:** MEDIUM

A newly added assertion in `contested.jsonl` or with `STRUCTURAL_PARADOX` is currently reported only as `ADDED_FACT`. Depending on the intended semantic meaning of `CONFLICT_INTRODUCED`, the projection has also gained a new conflict.

The protocol should decide explicitly whether addition/removal of a conflicted assertion co-emits conflict classes or whether those classes are reserved solely for status transitions of existing IDs. Add a fixture once that policy is governed; do not leave it accidental.

## Interaction with PR #59

`PROVENANCE_CHANGED` can only compare fields actually emitted by PR #59's canonical provenance output. The upstream AUD-ARCH-003 omissions for source lineage/evidence frame/observed evidence therefore also limit PR #64: the diff cannot report provenance that the projection never carries.

This is an upstream dependency, not a reason to duplicate inference in the diff tool.
