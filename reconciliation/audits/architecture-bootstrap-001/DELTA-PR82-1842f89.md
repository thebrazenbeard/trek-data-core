## Still-open #78 verifier findings

### AUD-1842-001 — CRITICAL — shared verifier still lacks cross-file referential/internal identity validation

No `projection_bundle.py` production change occurs in this successor.

The verifier still does not prove, among other deterministic invariants:
- active assertion IDs exist in assertion history;
- provenance assertion/evidence IDs match embedded assertion/evidence records;
- provenance support_set agrees with assertion support;
- embedded Evidence source/work IDs agree with embedded Source/Work records;
- repeated Source/Work/Evidence IDs across provenance rows carry identical metadata;
- assertion/reconciliation supersession targets exist;
- relation endpoints resolve to canonical/history catalogs where those types are represented;
- reconciliation subjects/evidence support resolve where represented;
- subject/object/observer embedded records match their advertised IDs.

A coherently rehashed dangling/contradictory graph can therefore still receive a verifier receipt.

The compiler itself emits coherent rows, but #78 defines the verifier as the consumer trust boundary precisely so consumers do not have to trust the producer.

### AUD-1842-002 — HIGH — relation-kind-specific verifier invariants remain absent

`projection-relation.schema.json` still uses one generic shape.

The verifier does not independently require:
- IDENTITY_LINK => LOCAL_ENTITY subject + LOCAL_ENTITY target + reconciliation_decision_id;
- ASSERTION_PREDICATE => assertion_id and compatible assertion/projection identity.

The compiler emits these stricter forms, but a tampered hash-consistent bundle can pass the generic row schema.

### AUD-1842-003 — HIGH — canonical row schema coverage remains incomplete

The shared verifier schema-validates relation and provenance rows, but not the full canonical shape of:
- assertion_history;
- reconciliation_history;
- entities;
- active projection assertion rows.

IDs and active status are checked, but malformed history/reconciliation/entity structure can remain hash-consistent and verifier-accepted.

### AUD-1842-004 — HIGH — derived builder identity still omits verifier schema dependencies

SQLite/PostgreSQL/graph-search builder identity still hashes the backend builder plus `projection_bundle.py`, but verifier behavior also depends on projection-manifest, projection-relation, and projection-provenance schema bytes.

A schema-only trust-contract change can therefore alter import behavior without changing `derived_builder_identity`.

Include verifier schema dependency identities in the shared verifier/tool identity and propagate that identity into each derived receipt.

### AUD-1842-005 — MEDIUM — PostgreSQL/graph bundle output hygiene remains non-atomic

PostgreSQL and graph/search still write declared outputs into an existing output directory without first rejecting/removing stale undeclared files or using atomic fresh-directory replacement.

SQLite correctly uses temp-file + `os.replace`.

File-only derived bundles should similarly ensure a new manifest cannot coexist with stale output bytes from a prior build.

### AUD-1842-006 — MEDIUM — relation mapping contract ID is still hard-coded rather than content-derived

Graph/search manifest uses `projection-relation.schema.json@0.2.0`, but the schema itself does not embed that version as a content identity and builder identity does not include the schema hash.

Prefer a governed version plus schema content hash, or derive the contract identity from the actual verifier dependency identity.
