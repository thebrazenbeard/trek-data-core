## Confirmed core remediation

### Compiler / reconciliation

The current compiler now:
- separates immutable assertion disposition from projection epistemic status;
- applies typed `ASSERTION_DISPOSITION` and `ASSERTION_PROJECTION_STATUS` decisions without rewriting worker records;
- defaults an effectively accepted assertion with no projection-status decision to `UNRESOLVED`;
- preserves PROPOSED/REJECTED/SUPERSEDED assertions in history while excluding them from active fact partitions;
- applies keyed `SCOPE_RESOLUTION` without opaque whole-scope replacement;
- represents identity decisions as typed relations/`identity_links` rather than generic global-identity collapse;
- rejects accepted EXPERIMENTAL identity relations;
- emits typed-reference assertion relation rows instead of inventing relation semantics from literals.

This substantially remediates original AUD-ARCH-002.

### Canonical provenance / manifest

The current canonical projection now emits eight required outputs:
- `entities.jsonl`
- `facts.jsonl`
- `relations.jsonl`
- `contested.jsonl`
- `unresolved.jsonl`
- `provenance.jsonl`
- `assertion_history.jsonl`
- `reconciliation_history.jsonl`

For each output the compiler records role/hash/count, and `projection_hash` is derived from the complete canonical output-hash set.

`provenance.jsonl` now preserves full reachable records rather than a narrow flattened subset, including:
- original assertion record;
- exact evidence support set;
- full Evidence record;
- full Source record plus transitive `derived_from` Source lineage records;
- full Work record plus parent Work lineage records;
- effective assertion disposition;
- disposition/projection/scope/entity-link decision IDs where currently wired;
- observer Local Entity record when present;
- typed subject record;
- typed object record when present.

This means changes to Source variant/hash/family/lineage, Evidence observed/frame/epistemic/fingerprint/observer fields, and Work structural fields become canonical-provenance changes and therefore projection-hash-visible when those records participate in assertion support.

This substantially remediates original AUD-ARCH-003. Source↔Work binding provenance remains correctly blocked on #65 because no binding implementation exists.

### Semantic diff

The diff engine now materially implements #67 and its corrections:
- deterministic same-ID and explicit-supersession pairing only;
- remove+add rather than fuzzy VALUE_CHANGED when no deterministic lineage exists;
- immutable same-ID assertion/entity/reconciliation changes fail closed;
- STABLE promotion/demotion semantics are separate from provisional non-STABLE state transitions;
- no conflict introduction/resolution inferred from status alone;
- explicit `CONTRADICTS` relation structure drives conflict events;
- scope keys diff independently;
- provenance changes can co-emit with status/value/scope events;
- entity/relation lifecycle uses explicitly provisional versioned classes where governance has not yet accepted canonical names;
- reconciliation-history-only changes use a provisional history class rather than fact VALUE_CHANGED.

This substantially remediates original AUD-ARCH-004.

## Surviving core findings

### AUD-CORE-205-001 — CRITICAL — inactive assertion successor still suppresses accepted predecessor

The compiler still computes:

`superseded_assertions = {a.supersedes for every assertion carrying supersedes}`

without considering the successor assertion's effective disposition.

Therefore a PROPOSED or REJECTED successor B can make accepted predecessor A effectively `SUPERSEDED` and remove A from active projection solely because B carries `supersedes: A`.

The validator contains the same conceptual rule when checking projection-status eligibility.

This violates the #72 separation between assertion lifecycle and active eligibility unless governance explicitly says a non-active successor deactivates its predecessor, which it currently does not.

Required regression:
1. A = ACCEPTED + valid projection status;
2. B = PROPOSED + `supersedes: A`;
3. A remains active;
4. define and test the exact effective-successor condition that does deactivate A.

This prevents full AUD-ARCH-002 closure.

### AUD-CORE-205-002 — HIGH / latent — ENTITY_LINK still invents singleton target cardinality

`decision_key()` keys active ENTITY_LINK decisions by:

`(ENTITY_LINK, subject_type, subject_id, relation_predicate)`

Thus one local entity cannot have two active targets under the same identity predicate.

#61 never defined all identity predicates as functional/one-target. Relations such as a future MERGED_FROM or SHARED_CAUSAL_HISTORY_WITH may legitimately be multi-valued.

All current identity predicates remain EXPERIMENTAL, so accepted bad data is currently fail-closed. Preserve that safe state.

Before any identity predicate becomes ACCEPTED, govern cardinality per predicate or use a nonexclusive key that includes target identity where appropriate.

### AUD-CORE-205-003 — HIGH — Work-level SCOPE_RESOLUTION has no general derived semantic surface

#61 permits SCOPE_RESOLUTION subjects of ASSERTION, WORK, or LOCAL_ENTITY.

Current compiler applies:
- Local Entity scope decisions to `entities.jsonl`;
- Assertion scope decisions to active assertion rows;
- subject scope decisions to an active assertion row when that Work/Local Entity is the assertion's direct subject.

There is no canonical Work output. A Work-level SCOPE_RESOLUTION whose Work is merely evidence context, or otherwise has no active assertion using that Work as its direct subject, has no derived scope effect outside `reconciliation_history.jsonl`.

That is history visibility, not deterministic application of the accepted scope resolution.

Required correction: define the canonical semantic surface for Work-level resolved scopes, likely through provenance/Work context or another governed output, and preserve its decision ID. Do not require a coincidental assertion with the Work as subject for the decision to become semantically visible.

### AUD-CORE-205-004 — MEDIUM/HIGH — canonical provenance omits subject-scope decision provenance

Active assertion rows correctly carry `subject_resolved_scope` and `subject_scope_resolution_decision_ids` when the assertion subject has Work/Local Entity scope decisions.

The corresponding provenance rows preserve assertion-scope decision IDs and entity-link decision IDs, but do not preserve the subject's scope-resolution decision IDs/resolved subject scope.

#76 requires relevant scope reconciliation provenance IDs to remain traceable in canonical provenance.

This is particularly important for Work subjects because Work scope has no independent canonical Work output.

### AUD-CORE-205-005 — HIGH — semantic diff cannot describe inactive assertion-history/provenance changes

The canonical projection intentionally includes `assertion_history.jsonl` and provenance rows for inactive PROPOSED/REJECTED assertions.

`semantic_diff()` pairs and compares provenance only for **active** old/new assertions. It does not diff assertion-history additions/removals or inactive provenance groups.

Consequences:
- adding a PROPOSED assertion changes `assertion_history.jsonl`, provenance, and `projection_hash`;
- changing provenance of a paired inactive historical assertion changes canonical output/hash;
- but no semantic event is emitted for those changes;
- with manifests present, the final guard raises `projection_hash changed but semantic diff produced no events`.

Fail-closed is preferable to misclassification, but the diff is incomplete over the canonical projection it claims to compare.

The protocol currently has proposed reconciliation-history lifecycle classes but no governed assertion-history lifecycle class. Director/governance should either:
- add a clearly provisional assertion-history change channel; or
- explicitly define history-only canonical changes as diagnostic/fail-closed until taxonomy is governed.

The current behavior should be documented/tested rather than discovered only when a PROPOSED assertion appears.

### AUD-CORE-205-006 — HIGH — identity relation semantic stability is tied to reconciliation decision ID

Identity-link projection rows use:

`relation_id = reconciliation:<decision_id>`

and entity `identity_links` embed the decision ID in the link object.

If an accepted identity decision is superseded by a new decision with the **same predicate and same typed target** but changed evidence/rationale, semantic relation meaning is unchanged but:
- entity `identity_links` differ because decision ID changed;
- relation ID changes, so old relation is removed and new relation added;
- diff emits ENTITY_LINK_CHANGED and provisional relation lifecycle events in addition to provenance/history change.

#67 reserves ENTITY_LINK_CHANGED for an actual governed identity relation/target change, not merely a new decision record supporting the same relation.

Required correction: separate stable semantic relation identity from reconciliation decision provenance. A same-semantics decision supersession should normally surface as provenance/history change, not a false link change.

### AUD-CORE-205-007 — HIGH — explicit contradiction can falsely resolve/reappear across assertion supersession

Typed-reference relation IDs are `assertion:<assertion_id>`.

If an explicit `CONTRADICTS` assertion is replaced through governed assertion supersession while preserving the same contradiction subject/target semantics, the relation ID changes with the assertion ID. The diff sees old CONTRADICTS relation removed and new one added, and can emit both CONFLICT_RESOLVED and CONFLICT_INTRODUCED even though the governed conflict structure persisted through explicit lineage.

#67 requires conflict events to describe actual conflict-set appearance/disappearance, not record-ID churn.

Required regression: explicit supersession of a contradiction assertion with the same contradiction target must preserve conflict continuity unless the conflict relation itself changes.

### AUD-CORE-205-008 — MEDIUM — projection-manifest schema weakened hash/count validation

The new manifest schema correctly requires the complete output set and role/hash/count structure, but hash-like fields are now generic strings rather than the earlier SHA-256-pattern-constrained fields:
- predicate_registry_hash;
- scope_key_registry_hash;
- input_hash;
- projection_hash;
- every output hash.

Output counts are integers but have no `minimum: 0`.

The compiler itself generates real SHA-256 values and nonnegative counts, so this does not corrupt compiler output. It weakens validation of externally supplied/tampered projection manifests exactly where #78 requires fail-closed verification.

Restore explicit hash format/algorithm constraints and nonnegative count constraints, or let the shared #78 verifier enforce an equivalently strict governed format.

### AUD-CORE-205-009 — HIGH — projection manifest is generated but not actually schema-verified in integrated CI

`projection-manifest.schema.json` is not part of the admission validator's schema map, and the workflow builds/diffs projections without invoking a projection-manifest verifier.

Repository search found no shared `verify_projection` implementation or tampered-manifest regression.

Therefore the stronger manifest schema exists as documentation/schema proposal, but consumer trust still depends on the builder behaving correctly rather than independent verification.

This is primarily #78, not a reason to undo #76 progress.

## Derived-adapter incompatibility exposed by the new canonical projection

The green end-to-end workflow currently uses an empty accepted corpus, so the derived builders see no nonempty assertion/provenance/history rows. They have not yet been adapted to the new canonical shape.

### AUD-DERIVED-205-001 — CRITICAL — inactive assertion provenance breaks SQLite and graph/search; PostgreSQL script would violate FK on execution

Current compiler emits provenance for every assertion in history, including PROPOSED/REJECTED assertions that are correctly absent from `facts|contested|unresolved`.

SQLite:
- imports only active partitions into `assertions`;
- provenance table has FK `assertion_id -> assertions.assertion_id`;
- then imports **every** provenance row.

Any inactive assertion with evidence therefore causes SQLite FK failure.

Graph/search:
- builds its assertion index only from active partitions;
- explicitly raises when provenance references an assertion absent from that active index.

PostgreSQL:
- generated schema similarly gives provenance a FK to active `assertions`;
- generation succeeds because SQL is not executed in CI, but execution with inactive provenance would fail.

This directly conflicts with #72/#76 historical assertion/provenance requirements.

Required fix: derived imported surfaces must represent or deliberately separate assertion history from active projection, and provenance must reference a table/surface that includes the historical assertion identities it can legitimately support.

### AUD-DERIVED-205-002 — HIGH — adapters read obsolete flattened provenance fields

Canonical provenance now stores full nested `source_record`, `evidence_record`, and `work_record` rather than the old flat convenience fields.

SQLite/PostgreSQL/graph-search still read top-level:
- `source_id`
- `work_id`
- `evidence_kind`
- `source_content_hash`

Those fields are not emitted by the new compiler.

Results on nonempty canonical projection:
- SQLite/PostgreSQL indexed provenance columns become NULL even though `record_json` retains the nested record;
- graph/search evidence nodes receive missing source/work/kind/hash metadata;
- graph/search omits EVIDENCE_SOURCE and EVIDENCE_WORK edges because `source_id`/`work_id` are absent at the expected location.

The adapters need a versioned canonical-provenance row contract, not field-name archaeology.

### AUD-DERIVED-205-003 — HIGH — reconciliation adapters still read obsolete raw `value`

The compiler's compatibility `accepted_reconciliation.jsonl` alias now contains typed reconciliation records with `payload`.

SQLite/PostgreSQL still populate `value_json` from `row.get("value")`, so typed decision payloads become NULL in indexed reconciliation columns while surviving only inside raw `record_json`.

Derived schema must expose typed payload semantics explicitly or declare them omitted in a versioned imported-surface contract.

### AUD-DERIVED-205-004 — HIGH — assertion history is silently omitted from all current derived imported surfaces

Canonical projection now requires `assertion_history.jsonl` because PROPOSED/REJECTED/SUPERSEDED assertions remain queryable/auditable.

Current SQLite/PostgreSQL/graph-search adapters consume active assertion partitions only and do not import assertion history as a distinct surface.

#78 allows derived consumers to omit canonical surfaces only through an explicit versioned imported-surface contract. No such contract exists.

This is not necessarily a mandate that every backend expose every history table identically. It is a mandate not to silently pretend the imported subset is the whole canonical projection.

### AUD-DERIVED-205-005 — CRITICAL — shared #78 projection verifier remains absent

All previous downstream trust findings remain:
- adapters trust `manifest.projection_hash` without recomputing/validating the canonical bundle;
- per-file declared hashes/counts are not verified before consumption;
- partition/status consistency is not independently verified;
- no separate derived-builder/schema identity or verified derivation receipt;
- SQLite deletes/replaces target before successful new build, violating #78 atomic-preservation rule;
- imported-surface subsets are undeclared.

The new canonical projection makes this more urgent, not less.
