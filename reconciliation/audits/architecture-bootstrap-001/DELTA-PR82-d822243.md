## Confirmed validator progress

### 1. Disposition vocabulary corrected

`DISPOSITIONS` is now `PROPOSED | ACCEPTED | REJECTED`; `SUPERSEDED` is no longer accepted as an ASSERTION_DISPOSITION payload. This aligns with Director #72.

### 2. Scope-key registry is now loaded and enforced

The validator loads `registry/scope_keys.json`, checks registry/methodology identity, uniqueness, subject-domain values, and definitions. SCOPE_RESOLUTION now:

- permits ASSERTION, WORK, or LOCAL_ENTITY subjects;
- requires exactly `resolution_key` + `resolution`;
- rejects ungoverned keys;
- enforces each key's allowed subject types.

This materially closes the previous free-form-key validator gap.

### 3. ENTITY_LINK validation is substantially safer

ENTITY_LINK now requires:

- `subject_type = LOCAL_ENTITY`;
- exact payload keys `relation_predicate`, `target_type`, `target_id`;
- `target_type = LOCAL_ENTITY` until another target schema is governed;
- registered IDENTITY_RELATION predicate;
- ACCEPTED decisions use only ACCEPTED predicates;
- PROPOSED decisions use only ACCEPTED/EXPERIMENTAL predicates;
- subject/object typing consistent with predicate metadata;
- target reference existence.

This correctly prevents the earlier invalid ACCEPTED EXPERIMENTAL SAME_AS/global-target pattern.

### 4. Assertion/reconciliation integrity improved

The validator now additionally:

- rejects duplicate assertion evidence-support IDs;
- validates assertion supersession cycles;
- expands predicate-registry structural/provenance checks;
- checks predicate inverse/supersession references;
- validates ASSERTION_DISPOSITION and ASSERTION_PROJECTION_STATUS payloads exactly;
- rejects ACCEPTED OTHER;
- checks projection-status decisions only target effectively ACCEPTED assertions after active disposition/supersession handling.

### 5. Path-wide research ownership hole materially resolved

A new `validate_partition_ownership()` scans every governed record under recognized research-lane paths, not merely records beneath a batch manifest root. Source, Work, and reconciliation-decision records are rejected anywhere under worker research partitions.

This closes the prior specific hole where a worker could place an authoritative Source/Work record elsewhere under `research/<lane>/` and satisfy referential integrity outside the batch root.

This does not create the missing Librarian-owned registry/binding surface; it establishes the negative ownership boundary only.

## New / remaining findings

### AUD-VAL-ENTITY-CARDINALITY — HIGH — ENTITY_LINK active-key cardinality is invented

`decision_active_key()` currently keys ENTITY_LINK as:

`(ENTITY_LINK, subject_type, subject_id, relation_predicate)`

and rejects more than one active accepted decision for the same key.

That silently imposes **at most one target per identity relation predicate per subject**.

Director #61 does not define that cardinality. More importantly, candidate identity relations can naturally have non-singleton cardinality. A future `MERGED_FROM` relation may require multiple antecedents; `SHARED_CAUSAL_HISTORY_WITH` could relate one local entity to multiple others. Predicate metadata currently has no cardinality declaration authorizing a one-target invariant.

Fail closed rather than inventing cardinality: either include target identity in the active key when duplicate exact links are the conflict, or explicitly govern per-predicate cardinality before rejecting multiple targets.

Required adversarial fixture: one subject + same relation predicate + two distinct valid targets must remain representable unless that predicate's accepted contract explicitly declares singleton cardinality.

### AUD-VAL-ASSERTION-SUPERSESSION — HIGH — inactive successor can suppress accepted predecessor during eligibility validation

For projection-status validation, `superseded_assertions` is computed from every assertion carrying `supersedes`, without checking the successor assertion's effective disposition.

Therefore a PROPOSED or REJECTED successor B that says `B.supersedes = A` can cause accepted predecessor A to be treated as effectively `SUPERSEDED`, making an otherwise valid projection-status decision on A fail.

Under #72, assertion lifecycle and projection eligibility are explicit. A non-active successor must not silently deactivate an accepted predecessor merely because a historical/proposal lineage pointer exists, unless governance explicitly defines that behavior.

Required fixture:
- A = ACCEPTED assertion with valid projection-status decision;
- B = PROPOSED assertion with `supersedes: A`;
- A must not become inactive solely because B was proposed.

A second fixture should establish the exact governed condition under which an accepted/effective successor deactivates its predecessor.

### Predicate use-level metadata still missing

The predicate registry and validator now enforce much richer metadata, but Director #55 explicitly requires predicate scope/level such as evidence-description, research assertion, reconciliation relation, or governed multi-level use. No such explicit field is currently required or validated.

`semantic_class` and `projection_eligibility` are not equivalent to a use-level contract. This remains a HIGH governance/typing gap because identity relations used in reconciliation should not automatically inherit research-assertion semantics.

### Actual registry still has no ACCEPTED identity predicate

All current IDENTITY_RELATION entries remain EXPERIMENTAL_ONLY. The validator correctly rejects them for ACCEPTED ENTITY_LINK decisions.

This is safe behavior, not a defect. It means the required positive ENTITY_LINK regression cannot honestly use the repository registry yet. Use an isolated fixture-local accepted identity predicate or explicitly govern/promote a real predicate through the proper process. Do not promote SAME_AS merely to make tests pass.

### Contract test still disagrees with governed scope key

`test_contract_alignment.py` at predecessor/current test bytes still uses `resolution_key: "continuity"`, while the governed registry now defines `CONTINUITY_SCOPE`. Because that test invokes the projection compiler directly rather than repository validation, it can encode a scope resolution the validator would now reject.

Update the oracle to use the actual governed key before treating compiler behavior as contract-aligned.

### Librarian positive ownership still unresolved

The validator now proves where authoritative Source/Work records may **not** live. It still cannot prove they live on an accepted Librarian-owned registry/binding surface because issue #14/#65 implementation does not yet exist. Do not label full Source/Work ownership closure from negative path rejection alone.
